# Navi 导航站 — 技术文档

> 版本 v6　日期 2026-07-25　状态：与代码对齐
> 关联：[需求文档](需求文档.md)

本文件记录**怎么做（How）**与关键技术决策，目标是让后续维护者能快速理解架构与取舍。功能需求见[需求文档](需求文档.md)。

## 1. 技术栈与选型

| 层 | 选型（版本） | 理由 | 否决的备选 |
|---|---|---|---|
| Web 框架 | **Hono 4** | 同一份代码可跑 Workers / Node / Bun；轻量、TS 友好 | Express（跑不了 Workers）；itty-router（生态弱） |
| 数据层 | **Drizzle ORM** | 一套 schema/查询，驱动切换 D1 / better-sqlite3；方言均为 SQLite，迁移统一 | Prisma（对 Workers/D1 偏重）；Kysely（可选但 Drizzle 关联查询更顺） |
| 语言 | **TypeScript 5.9** | 全栈共享类型 | — |
| 校验 | **Zod 4** | 请求体 / 导入 JSON 校验，前后端共享 schema | — |
| 密码哈希 | **Web Crypto PBKDF2** | Workers 与 Node 都原生支持，零原生依赖 | bcrypt（Workers 跑不了原生模块）；argon2-wasm（更强，留作升级项） |
| 会话 | **DB session + cookie** | 便于即时吊销/登出/停用立即生效 | JWT（吊销麻烦） |
| 前端 | **Vue 3.5 + Vite 8（SPA）** | 富交互（浮层级联、多选、即时筛选）顺手可维护；静态产物两端易托管 | SSR+htmx（交互别扭）；全栈框架（两端对等约束下偏重/锁定） |
| 前端配套 | Vue Router 5 · Pinia 3 · vue-i18n 11 · Tailwind CSS 4 | 路由 / 状态 / 国际化 / 原子化样式 | — |
| 抓取解析 | music-metadata（前端提取音频封面） | 复用 Cache API 音频 Blob 读取封面，无需服务端 | — |

**部署目标**：Cloudflare（Workers + D1）与 Docker/自托管（Node + better-sqlite3）**完全对等**。

## 2. 架构与项目结构

核心原则：**只有两个薄适配层是运行时相关的，其余全部共享**——这是"两端对等"低成本的关键。

```
src/                     # 后端（运行时无关 + 两处适配层）
  app.ts                 # 组装共享 Hono app（挂载所有路由与全局中间件）
  db/
    schema.ts            # Drizzle 表定义（唯一数据真相）
    client.ts            # ★适配①：Workers→D1 驱动 / Node→better-sqlite3
    tx.ts                #   原子写封装：Node 用事务 / D1 用 db.batch()
    migrate.ts           #   Node 启动时应用迁移（数据回填一律写成 SQL 迁移，不放这里）
    migrations/          # drizzle-kit 生成的 SQL（一份，两端各自应用）
  services/              # 业务逻辑（运行时无关，依赖 db 接口 + 注入的 fetch）
    bookmarks.ts  tags.ts  engines.ts  defaultEngines.ts  prefs.ts  users.ts
    sessions.ts  password.ts        #   会话与密码哈希
    fetcher.ts  metadata.ts  ssrf.ts #   抓取 + HTML 解析 + SSRF 防护
    likeEscape.ts                    #   SQL LIKE 通配转义
    sloganMarkup.ts                  #   标语行内标记解析（加粗/斜体/删除线/颜色）
    transfer.ts                      #   导入导出
  routes/                # Hono 路由（薄，调 services）
    setup.ts  auth.ts  adminUsers.ts  tags.ts  bookmarks.ts
    engines.ts  prefs.ts  fetch.ts  bing.ts  transfer.ts
  middleware/            # auth（session + requireAuth/requireAdmin）/ rateLimit
  server/
    config.ts            #   secureCookie 等运行时配置解析
    node.ts              # ★适配②：Node 入口（serve API + 静态资源 + DNS 复核抓取）
    worker.ts            # ★适配②：Workers fetch handler + D1 绑定 + assets
web/                     # 前端 Vue 3 SPA（★顶层目录，非 src/web/；Vite 构建为静态资源）
  src/
    api/                 #   fetch 客户端 + 响应类型
    components/          #   atoms / molecules / tags / home / layout / manage
    composables/         #   useTheme / useToast / useConfirm / useBackground / useBingWallpaper / useSloganFont / useHotkeys / useResponsivePageSize / useResponsivePanelCount
    stores/              #   Pinia：auth / bookmarks / tags / engines / prefs / music / adminUsers
    views/               #   页面（含 settings/ 各分区）
    layouts/  router/  i18n/  lib/
tests/                   # 后端单测 + 集成（Vitest, node 环境）
docs/                    # 需求文档 / 技术文档
scripts/                 # copy-migrations.mjs（构建时拷迁移到 dist/server）
```

- **共享**：schema、services、routes、middleware、前端——一份代码。
- **仅两处不同**：`db/client.ts`（选驱动）；`server/node.ts` vs `server/worker.ts`（入口与静态资源托管）。
- services 仅依赖 Drizzle 的 db 接口与注入的 `fetch`（两端都有），故业务逻辑两端通用。
- 配置走环境变量：Node 用 `process.env`（`DATABASE_FILE` / `PORT` / `SECURE_COOKIES` / `NODE_ENV`），Workers 用 `wrangler.toml` 的绑定（D1 `DB`、静态资源 `ASSETS`）。会话为 DB 中的随机 token（不签名），无需会话密钥。
- **事务差异**：多表原子操作在 Node 用事务、在 D1 用 `db.batch([...])`（D1 不支持交互式事务），统一封装在 `db/tx.ts` 的 `runWrite`。

## 3. 数据模型

**通用约定**：除 `sessions` 外，每表均含 `id`（主键）、`created_date`、`last_modified_date`（审计字段，见 `schema.ts` 的 `audit` mixin），并配检索索引。

**外键策略**：**不设 DB 层外键约束**（不写 Drizzle 的 `references()`），`user_id` 等为普通带索引列；关联与级联在 service 层手动处理（事务/batch）。理由：现代实践 + 规避 D1 外键级联/PRAGMA 的坑，保证 D1 与 SQLite 行为完全一致、可预测、可审计。ERD 连线仅表示逻辑关系。

**账号隔离**：所有用户数据表都带 `user_id`，每条查询强制按当前用户过滤。

### 3.1 表定义（共 7 表）

| `is_active` | INTEGER（布尔） | 启用状态，默认 `true`（置 `false` 即停用，会话立即失效） |

| `page_size` | INTEGER | 列表每页数量，默认 `24`（同上，前端自适应） |

### 3.2 关系与级联

- `users` 1 ──< N `bookmarks` / `tags` / `search_engines` / `sessions`；1 ──1 `user_prefs`
- `bookmarks` N >──< M `tags`（经 `bookmark_tags`）
- `tags` 自引用 `parent_id` 形成层级；`path` 便于"按父查子"
- 删 user → 手动级联删其全部数据；删 tag → 手动级联删子树 + 解除网址关联（**不删网址**）；删 bookmark → 删其 `bookmark_tags` 行

## 4. 认证与安全

1. **首启向导**：库中无任何用户时，前端所有访问重定向到 `/setup` → 填管理员邮箱+密码 → 建首个 admin（并自动登录）。存在用户后 `POST /setup` 返回 `409 already_initialized`。
2. **登录**：邮箱+密码 → 校验 PBKDF2 → 建 `sessions` 行 + 下发 `httpOnly + SameSite=Lax`（生产加 `Secure`）cookie `navi_session`（存 token，初始有效期 30 天）。`must_change_password` 为真则前端强制改密。
3. **会话中间件**（`middleware/auth.ts` + `services/sessions.ts`）：每请求校验 session（未过期 + 用户 `is_active`）→ 注入当前用户到 `c.var.user`；剩余有效期不足 7 天时把 DB 与内存缓存中的 `expires_at` 滑动续至当前时间后 30 天。停用账号/删 session 立即失效，过期 session 自清理。cookie 的 `Max-Age` 固定为 30 天，活跃请求会重新下发以同步浏览器期限。
4. **CSRF 与请求体封顶**：Hono `csrf()` 全局同源校验（Origin 检查，作用于所有写方法）+ `SameSite=Lax` 打底。这些全局中间件与会话解析均**仅挂在 `/api/*`**（静态资源不跑鉴权/续期写）。另有 `bodyLimit` 对 `/api/*` 施加 8MB 请求体上限（封顶超大 payload 的内存/存储/解析成本，8MB 足够最大导入文件），超限 **`413 payload_too_large`**；字段级另有 zod `.max()`（见第 11 项）。
5. **登录限流**（`middleware/rateLimit.ts`）：滑动窗口，按 `ip:email` 计失败次数，默认 10 次 / 15 分钟，成功即重置；超阈值 `429 too_many_attempts`。内存态，Workers 上为单 isolate 尽力而为。
6. **SSRF 防护（抓取）**（`services/ssrf.ts` + `fetcher.ts`）：仅允许 http/https → 拒绝凭据/私网/环回/链路本地/云元数据（`127/8`、`10/8`、`172.16/12`、`192.168/16`、`169.254/16`、`::1`、IPv4-mapped、CGNAT 等）→ **每次重定向重新校验**（手动跟随，防重定向/DNS rebinding）→ Node 入口注入 `dns.lookup` 对解析 IP 二次复核 → 限超时 5s + 响应体 512KB 上限 + 最多 4 跳 → 仅提取所需 meta/favicon。
7. **密码哈希**（`services/password.ts`）：PBKDF2-HMAC-SHA-256，10 万迭代 + 每用户 16B 随机盐 + 32B 派生密钥；存储格式 `pbkdf2$<迭代>$<saltB64>$<hashB64>`（自带参数，便于升级）；常量时间比较。
8. **登出**：删 session 行 + 清 cookie；`logout-all` 删该用户全部 session。
9. **导入导出二次确认**（`routes/transfer.ts`）：导出（`POST /api/export`）与导入（`POST /api/import`）均为敏感操作（整库读出 / 覆盖），除会话外再要求随请求体带**当前密码**，服务端复用 `verifyCredentials` 校验（与改密同款），失败返回 **400 `{ error:'wrong_password' }`**。密码走请求体（非 URL query，不进浏览器历史/访问日志），依赖 TLS 保护传输——因此公网部署务必启用 HTTPS。前端由通用密码确认弹窗 `PasswordConfirmModal` 收集，校验通过才真正执行。
10. **依赖安全**：定期跑 `pnpm audit`。生产制品的依赖面很小：后端 bundle 内联全部 JS 依赖（以 `package.json` 的 `dependencies` 为准），Docker runtime 层只额外安装唯一的外部原生依赖 `better-sqlite3`（精确版本钉死在 `docker/package.runtime.json`，升级主 `package.json` 的 better-sqlite3 时需同步），当前均无告警。策略为**成熟优先**：仅在有安全/EOL/阻塞性驱动时升大版本，否则随 `pnpm update` 吃 caret 内补丁。`drizzle-orm` 已升至 `0.45.2` 修复标识符转义 SQL 注入（GHSA-gpj5-g38j-94v9；本项目未使用 `sql.raw`/`sql.identifier` 拼接用户输入，属纵深防御）。其余审计告警均来自 **devDependencies 的传递依赖**（`vitest`/`vite`/`esbuild`/`glob` 等），仅在本机开发服务场景可利用，**不进入生产制品**，已评估暂不追升。
11. **资源数量上限（防刷库）**（`services/limits.ts` + `routes/schemas.ts`）：两类边界，性质不同、分处两地——
    - **每用户资源配额**（`limits.ts`）：网址 10000 / 标签 1000 / 引擎 100，取值「防小人不防君子」（正常用户碰不到，仅挡脚本化批量刷库）。**有状态**：`assertWithinLimit` 先 `count(*)` 查该用户现有行数再断言，创建单条默认 `adding=1`；导入按最终数量用 `assertCountWithinLimit` 预检（replace 模式下旧行即将清空，不查实时值）。超限抛 `LimitExceededError` → 路由返回 **409 `{ error:'limit_exceeded', resource, limit }`**（前端 `lib/limitError.ts` 识别并提示）。刻意不做成环境变量（无按部署调优的真实需求）。
    - **请求体形状校验**（`schemas.ts`）：音乐播放列表 ≤20 首（`MAX_MUSIC_TRACKS`）、单曲名 1-100 字、slogan 可见文本 ≤80 字（`MAX_SLOGAN_LENGTH`，经 `sloganMarkup.stripSloganMarkup` 剔除行内标记后计数）、slogan 原始串 ≤1000 字（`MAX_SLOGAN_RAW_LENGTH`，封顶含标记的存储/传输/解析成本）。**无状态**：只看单个请求 payload，zod 的 `.max()`/`.refine()` 断言，不合法即 **400**，进不到业务逻辑。这类常量因不查库、被 prefs/transfer 两路由共用，集中在 `schemas.ts`（连同共享的 `musicTrackSchema`），与 `limits.ts` 的有状态配额区分开。

## 5. API 设计

统一前缀 `/api`，session cookie 鉴权，写操作经全局 `csrf()` 同源校验，请求/响应体用 Zod 校验。`/api/*` 响应带 `no-store` 头。资源不存在或越权访问统一返回 `404 not_found`；请求体校验失败返回 `400 { error, issues }`。

**公共（免登录）**
- `GET /api/health`、`GET /api/setup/status`、`POST /api/setup`（建首个 admin）
- `POST /api/auth/login`（限流）、`POST /api/auth/logout`
- `GET /api/bing/wallpaper`（Bing 每日壁纸 URL，24h 内存缓存 + 出错回退旧值）

**auth**：`POST /api/auth/logout-all`、`GET /api/auth/me`、`POST /api/auth/change-password`

**admin/users**（管理员）：`GET`、`POST`（建号，`must_change_password=true`）、`PATCH /:id`（停用/启用、提升管理员、改显示名、重置密码）、`DELETE /:id`；均有"最后一个管理员"守卫。

**tags**：`GET`（`parent_id` 未传→全部、`=null`→根、`=N`→子级带 childrenCount）、`POST`、`POST /bulk-delete`、`PATCH /:id`（改名/移动，重算 path，防环）、`DELETE /:id`（级联子树 + 解除关联）

**bookmarks**：`GET`（`tags` 交集 + `q` 模糊 + `sort`/`dir` + `status` active/inactive/all + `page`/`pageSize`）、`POST`、`GET /:id`、`PATCH /:id`、`DELETE /:id`；`GET /recent`、`DELETE /recent`（清空最近）、`DELETE /recent/:id`；`GET /top`（首页三榜单，见 §6.4）；`POST /bulk-delete`、`POST /bulk-tags`（assign|remove）；`POST /:id/visit`、`POST /:id/fetch`（抓取并回填）

**engines**：`GET`（按 `sort_order`）、`POST`（模板须含 `{query}`）、`PATCH /:id`、`DELETE /:id`、`POST /:id/default`、`PUT /reorder`（按提交的 ID 顺序重写本人引擎的 `sort_order`）

**prefs**：`GET`（惰性建默认行）、`PATCH`（recentCount / pageSize / defaultSort / background* / musicPlaylist / slogan，均带范围校验；playlist ≤20、slogan ≤80）。注：recentCount / pageSize 仍是库中字段与 PATCH 入参，但前端已改由视口自适应（见 §7），偏好页不再暴露手动设置。

**fetch**：`POST /api/fetch/metadata`（只抓取返回元数据、不落库）

**import/export**（`transfer.ts`，挂在 bare `/api`、逐路由 `requireAuth`）：`POST /api/export`、`POST /api/import`（`mode=merge|replace` 在请求体内）。二者均为敏感操作（整库读出 / 覆盖），除会话外**再要求当前密码二次校验**——请求体带 `password`，服务端用 `verifyCredentials` 复核，错误返回 `400 wrong_password`（故 `/export` 用 POST 而非 GET，以携带密码体）。服务端格式仍为 Navi JSON；浏览器书签 HTML 在前端由 `lib/browserBookmarks.ts` 解析/序列化后复用同一导入导出 API。

## 6. 关键流程与算法

1. **抓取**：填 URL → `fetch/metadata` 或 `bookmarks/:id/fetch`（SSRF 校验 → 限时/限大小 fetch → 解析 `<title>` / `meta description`·`og:*` / favicon `<link>` 并转绝对 URL）→ 回填可改 → 保存。favicon 存解析出的绝对 URL（热链）。抓取失败返回 `502 fetch_failed`。
2. **标签"父含子" + 交集查询**：每个选中标签先按 `path` 前缀展开为"含全部子孙"的标签组；网址需**同时命中每个标签组**（组间交集、组内含子级），用 `EXISTS`/join 实现；模糊 `q` 在筛选结果内叠加；按 `sort`/`dir` 排序 + 分页（含 `visits` → `visit_count`）；`status` 控制 active/inactive/all。
3. **模糊搜索（LIKE，非 FTS5）**：`services/likeEscape.ts` 的 `likePattern` 转义 `\ % _` 并 `lower()` 转小写（CJK 原样）、两端加 `%`；SQL 侧对 `name` / `description` / `url` 做 `lower(col) like ? escape '\'` 的子串匹配。选择 LIKE 而非 FTS5：数据量个人级、免维护虚拟表与触发器、两端行为一致。
4. **最近访问与访问次数**：点击 → `POST /:id/visit` 更新 `last_visited_at` 并原子累加 `visit_count`（仅 active）再跳转；`GET /recent` 取 `last_visited_at` 倒序前 N（排除 inactive）；「清除」= `DELETE /recent` 将本人网址的 `last_visited_at` 置空，不清零 `visit_count`；列表可按访问次数排序。**首页侧栏三榜单**：`GET /top?limit=N` 一次返回 `{visits, weight, created}` 三份精简列表（同 `RecentBookmark` 字段，仅 active、limit 钳 ≤50）——visits 按 `visit_count` 倒序（过滤 0 次）、weight 按权重倒序（新建默认 100；过滤 weight=0，负权重沉底）、created 按创建时间倒序（不过滤）；三榜**只读**，清空/单删仅「最近访问」支持（刻意的产品决策）。
5. **背景图**：`background_type` 三态——`none` 无图；`bing` 取 `GET /api/bing/wallpaper`（后端代理 + 缓存）；`custom` 用 `background_image_url`。**透明度语义**：DB 存"背景可见度"0-100，前端反相为遮罩层不透明度 `overlay = (100 - 可见度)/100`，暗色用黑遮罩、亮色用白遮罩（`composables/useBackground.ts`）。
6. **拖拽排序**：`composables/useDragReorder.ts` 基于 Pointer Events 统一鼠标/触屏拖拽。搜索引擎重排由 store 乐观更新并调用 `PUT /engines/reorder`，失败回滚；音乐列表只改本地数组，点击保存后随 `PATCH /prefs` 落库。
7. **音乐播放器**：播放列表存 `user_prefs.music_playlist`（JSON，≤20 条，每项 `{url, name}`）经 `PATCH /prefs` 持久化；音量/循环模式存浏览器 `localStorage`；封面用 `music-metadata` 复用已缓存音频 Blob 读取；音频经 Cache API（`navi-audio-v1`）缓存，失败回退直链。
8. **个性签名 slogan**：文本存 `user_prefs.slogan`（可见文本 ≤80、原始串 ≤1000，见 §4.10）；支持行内标记——`<b>` 加粗、`<i>` 斜体、`<s>` 删除线、`<c=#hex|颜色名>` 着色，大小写不敏感、可嵌套。解析逻辑在 `services/sloganMarkup.ts`（服务端 `stripSloganMarkup`，供长度校验）与 `web/src/lib/sloganMarkup.ts`（前端 `parseSlogan`，供 `HomeSlogan.vue` 渲染为段）两端各一份；未闭合 / 不匹配 / 非法颜色的标记**一律原样降级为字面文字**，绝不吞掉用户内容，颜色仅接受十六进制（`#rgb`/`#rrggbb`/`#rrggbbaa`）与精选颜色名白名单。偏好页输入框对原始长度做客户端预检：trim 后超过 1000 时切换为红色错误提示并短路保存（不发 PATCH），与 `sloganSchema` 的 `.trim().max(MAX_SLOGAN_RAW_LENGTH)` 口径一致，避免发出注定被 400 拒绝的请求。**字体选择仅存浏览器 `localStorage`（`navi_slogan_font_family`），不入库**，通过 Local Font Access API 枚举本地字体。
9. **浏览器书签兼容**：`lib/browserBookmarks.ts` 使用浏览器 `DOMParser` 容错解析 Netscape Bookmark File Format；目录转标签 path，根目录特征层自动剥离，空目录忽略，同 URL 多目录合并为多标签。导出时标签 path 还原为多层目录，多标签网址在各目录各写一份，无标签网址放根目录。
10. **网址卡片键盘导航**：`composables/useGridNavigation.ts` 从卡片实际 `getBoundingClientRect()` 推断行列，方向键移动原生按钮焦点；网格外首次按方向键聚焦第一张卡片，浏览器原生 `Enter` 激活链接。输入态、弹窗与 IME 组合输入由 `useHotkeys.ts` 统一避让。
11. **PWA 元数据**：`web/public/manifest.webmanifest` 声明 `standalone`、主题色与 192/512 普通及 maskable 图标；`web/index.html` 引入 manifest 与 Apple Touch Icon；静态响应头对 manifest 与图标设置 `no-cache, must-revalidate`，确保更新及时生效。当前未注册 Service Worker，不承诺离线可用。
12. **缓存策略**：
   - **后端（进程内存）**：sessions、users、prefs、engines、tags 五个 service 均在模块级维护 `WeakMap<DB, Map<key, data>>` 缓存。读路径命中缓存直接返回 clone 副本（防外部修改污染）；写操作后主动 invalidate 对应条目；删除用户时级联 invalidate 其全部关联缓存。WeakMap 以 DB 实例为键，Node 长驻进程中常驻直至 invalidate；Workers 端 `worker.ts` 在模块级缓存 DB 实例（同一 isolate 复用期间共享），isolate 回收时缓存随实例自动释放。无 TTL，靠写后失效保证一致性——适用于个人级数据量、单实例部署场景。
   - **前端（请求级）**：bookmarks store 对列表请求做短 TTL（1s）缓存 + in-flight 去重（同参数并发请求共享同一 Promise）+ 竞态保护（仅最新一次 requestId 的响应写入 state）；任何写操作后清空缓存强制下次 reload。首页侧栏面板（`/bookmarks/recent` 与 `/bookmarks/top`）另有一套更长 TTL（30s）的同款缓存（`cachedRailsGet`），配合侧栏懒加载吸收「榜单间来回切换」与 visibilitychange（切回标签页）触发的重拉，避免重复请求；两套缓存由 `invalidateAfterWrite` 在所有写操作（visit / 增改删 / 批量操作 / 清除最近访问）后统一失效。
13. **首页排序切换（会话级）**：首页筛选行的排序下拉（`HomeView.vue` 的 `BaseSelect`，底层为自绘 `BaseListbox`）绑定 `bookmarks` store 的 `sort`，初值取自偏好 `defaultSort`；切换时 `onSortChange`（接收选定值）调 `setSort`（store 内重置到第 1 页）后立即 `load()`，**不调用 `prefs.update`**，仅当前会话生效、不写回 `user_prefs.default_sort`。与 §6.6 的引擎 / 音乐拖拽排序（落库持久化）形成对照——首页排序刻意不持久化，偏好页仍是修改默认排序的唯一入口。

## 7. 前端架构

- **Vue 3 + Vite（SPA）**，构建为静态资源，两端均可托管（Workers assets / Node 静态中间件）。全部组件用 `<script setup>` + 类型式 `defineProps/defineEmits`。
- **页面**：起始页（游客/登录后 `HomeView`）、登录、改密、首启向导、设置（`SettingsLayout` 左侧分组侧边栏 + 嵌套路由分区，`views/settings/` 下各分区）。设置分区分四组——**内容**（搜索引擎/网址管理/标签）、**偏好**（显示/标语/背景/音乐）、**账户**（导入导出/密码）、**管理**（用户，仅管理员）；进入 `/settings` 默认重定向到「搜索引擎」（即「内容」组首项，与侧边栏顺序、`AccountMenu` 的「设置」入口三者一致）。
- **组件分层**：`atoms`（Base* 基础件——含 BaseInput/**BaseSelect**（字段样式单选下拉，内部基于 `molecules/BaseListbox`，非原生 `<select>`）/BaseCheckbox/**BaseRadio**（与 Checkbox 成对的单选原子）等 + Favicon）/ `molecules`（BaseCard/BaseModal/BaseDropdown/**BaseListbox**（自绘单选 listbox 底座，见下）/ToastHost/**ConfirmHost**（全局确认弹窗容器）/**PasswordConfirmModal**（敏感操作前的当前密码确认）/列表工具条/分页/排序）/ `tags`（跨页复用的级联标签选择器 TagCascadePopover/TagCascadePicker 与 TagChips）/ `home`（搜索条、卡片网格、侧栏分段单开面板 HomeRails/RailPanel、音乐、slogan）/ `layout` / `manage`（各编辑弹窗）。
- **状态/数据**：Pinia setup 式 store（`useXStore`）；`api/client.ts` 统一 fetch + CSRF 头；`composables/` 封装主题/toast/背景/Bing/字体等副作用。
- **全局确认弹窗**（`composables/useConfirm.ts` + `molecules/ConfirmHost.vue`）：仿 `useToast` 的模块级单例——`ConfirmHost` 在 `App.vue` 根挂载一次，`useConfirm().confirm({ message })` 返回 Promise（确认 resolve(true)、取消/关闭 resolve(false)），复用 `BaseModal` 继承焦点陷阱/Esc/进入动画。设置页所有删除的二次确认统一走它，**不再使用浏览器原生 `confirm()`**（风格一致、可无障碍）。
- **自绘单选下拉底座**（`molecules/BaseListbox.vue`）：在 `BaseDropdown` 浮层原语（Teleport 脱层叠上下文 / fixed 定位 / 遮罩点击关闭 / Esc / 滚动重定位）之上补齐 listbox 语义，替代原生 `<select>`——移动端不再弹系统 picker（iOS 滚轮 / Android 弹窗），双端一致且可主题化/暗色化，展开态可反映到 chevron 翻转（原生 `<select>` 无法感知）。选项经 `:options="[{ value, label, disabled? }]"` 传入；`#trigger`/`#option` 插槽支持自定义触发器与选项渲染（引擎 favicon、字体预览）。无障碍走 ARIA 1.2「Select-Only Combobox」模式：触发器 `role=combobox`+`aria-haspopup=listbox`+`aria-expanded`+`aria-controls`+`aria-activedescendant`，浮层 `role=listbox`、选项 `role=option`+`aria-selected`；焦点常驻触发器、用 `aria-activedescendant` 承担 roving。键盘完整覆盖：闭合时 ↑↓/Enter/Space/可打印字符打开，展开时 ↑↓ 移动、Home/End 首末、Enter/Space 选定、Esc 关闭回焦、Tab 关闭放行、可打印字符 typeahead（500ms 缓冲）；触控设备选项 ≥44px。两个消费方：`atoms/BaseSelect`（字段样式，5 处排序/筛选/字体）与 `home/EngineSelector`（首页搜索引擎切换，favicon + 名称）。
- **响应式数量自适应**：侧栏面板条数与网格每页数量不再由用户手动配置，而是按视口实测尺寸计算——`useResponsivePanelCount`（侧栏单开面板的条数，让选中面板铺满分段条以下的全部侧栏高反解，上限 50 对齐后端 limit）、`useResponsivePageSize`（首页网格：桌面列数按网格容器实测宽度反解 `clamp(floor((宽+16)/(190+16)), 4, 8)` 并以 `--bm-cols` 下发，避免侧栏挤压后按视口分档塞入过多列；每页数量按列数取整避免末行残缺）、`useResponsiveTablePageSize`（设置页表格）。库中 `recentCount`/`pageSize` 字段与默认值保留但前端不再写入。
- **首页侧栏分段单开面板**（`HomeRails.vue` + `RailPanel.vue`）：最近访问 | 访问次数 / 自设权重 | 创建时间 四榜单，**全尺寸统一**为「玻璃分段条 + 单开内容卡」——上方一行等分四段做切换、下方只展示选中的那一个面板并 `flex-1` 铺满分段条以下的侧栏可用高（列表自身滚动）；**永远恰好一个展开**（默认最近访问，`select` 点当前选中段无效，无全收起空态），选中项仅会话内。桌面（≥1024px）侧栏为左列（宽 15/18/20rem，lg/xl/2xl）；手机（<1024px）坍缩到网址列表上方堆叠、允许滚动。面板条数由 `useResponsivePanelCount` 按视口高反解、同时作为 `/recent` 与 `/top` 的 limit（同源）。选中态由 `HomeView` 持有（`v-model:selected`）并**懒加载**：只拉当前选中面板的数据——最近访问走 `/bookmarks/recent`，三榜单（visits/weight/created）共用一次 `GET /bookmarks/top`（返回三份），故进页只发一次 `/recent`、首次切到任一榜单才发一次 `/top`、榜单间再切走命中缓存。挂载、切换面板、条数变化（resize）、回前台（visibilitychange）、书签增改删保存后，均只重拉**当前可见**面板（其余等切过去按需拉）。仅最近访问面板有清空/单删。
- **键盘快捷键**：`composables/useHotkeys.ts` 声明式注册 document 级 keydown（挂载/卸载自动增删）；公共守卫——IME 组合中（`isComposing`）与长按重复（`repeat`）不触发，单键在输入控件内让位于打字（`⌘/Ctrl+K` 例外）。首页注册 `/`·`⌘/Ctrl+K`（聚焦网页搜索）、`s`（站内搜索）、`n`（新增网址）、`p`（播放/暂停）、`Esc`（清空失焦）、`?`（帮助面板 `ShortcutHelpModal`）；键位表见[需求文档](需求文档.md) §5.9。

## 8. 部署

- **Cloudflare**：Workers + D1 绑定 + 静态资源；`wrangler.toml` 配 D1 绑定（`DB`）、静态资源绑定（`ASSETS`）与 `migrations_dir`；drizzle-kit 生成迁移，`wrangler d1 migrations apply` 应用；首启向导建管理员。仅需前端产物 `dist/client`，入口 `src/server/worker.ts`。详见 [DEPLOY_CLOUDFLARE.md](../DEPLOY_CLOUDFLARE.md)。
- **Docker / 自托管**：Node 入口 + better-sqlite3，SQLite 文件挂卷；多阶段 Dockerfile（`node:22-slim` 构建 SPA+服务 → runtime 层经 `docker/entrypoint.sh` 降权为 `node` 用户运行 `node dist/server/node.js`，含健康检查与 `sqlite3` CLI）+ docker-compose（绑定挂载 + env）；`migrate.ts` 在启动时应用迁移（数据回填也走 SQL 迁移）；TLS 交反向代理（如 Caddy）。**Node 要求 ≥22**（见 `package.json` 的 `engines` 与 `.nvmrc`）。
- 配置一律走环境变量；迁移 SQL 一份，两端各自应用；构建时 `scripts/copy-migrations.mjs` 把迁移拷进后端 bundle。
- 本地开发数据库文件、`.wrangler/`、`.dev.vars` 均已在 `.gitignore` 忽略。

## 9. 测试策略

- **单元（Vitest，node 环境，`tests/`）**：services、**SSRF 防护**（私网/重定向/rebinding 拦截）、密码哈希、标签子树展开 + 交集查询构造、LIKE 转义、导入导出序列化。
